# Тестирование и внедрение аптечного интерфейса витрины и рабочих мест

Репозиторий содержит материалы лабораторной работы по верификации, регрессионному тестированию и развертыванию (деплою) локальной модели многопользовательской аптечной системы бронирования.

## Как запустить стенд
1. Склонируйте репозиторий: `git clone https://github.com`
2. Перейдите в папку проекта и откройте файл `src/index.html` в любом современном браузере (Chrome, Edge, Firefox).

## Структура репозитория и описание файлов

*   **`REPORT.md`** — главный отчетный документ (протокол испытаний). Содержит подробное описание всех 21 тест-кейса (с шагами, ожидаемыми и фактическими результатами), карты зафиксированных дефектов с анализом регрессии, разбор инцидентов службы поддержки (INC-1, INC-2, INC-3), а также экспертное заключение по границам проверки и обоснование релиза.
*   **`README.md`** — путеводитель по репозиторию (текущий файл), содержащий инструкции по запуску, краткий перечень выполненных задач и описание структуры проекта.
*   **`pharmacy-prod-backup.json`** — эталонный снимок (бэкап) базы данных рабочего контура (модели продакшена), сделанный и скачанный вручную строго до проведения обновления конфигурации. Хранит данные о 2 контрольных заказах схемы v1.
*   **`pharmacy-session.json`** — очищенный и дополненный файл полной сессии тестирования. Содержит упорядоченный хронологический лог системных событий, включая успешные проверки, переключения версий API, триггеры сбоев сети и финальный факт деплоя сборки 1.5.1.
*   **`.gitignore`** — конфигурационный файл Git, исключающий индексацию локального мусора ОС, временных кэшей редакторов кода (`.vscode`, `.idea`) и системных логов.
*   **папка `src/`** — изолированная директория с исходным кодом локального веб-стенда аптечной системы бронирования (`index.html`, `practice.html`, `app.js`, `data.js`, `styles.css`).

## Что было выполнено в ходе работы:
- Проведено приёмочное тестирование сборки `1.5.0-rc` и выявлено 3 критических дефекта (P1) в логике поиска, промокодов и изоляции остатков конкретных точек продаж.
- Проанализирована совместимость контрактов данных (API v1 в рублях против API v2 в копейках).
- Проведено полное регрессионное тестирование на исправленной сборке `1.5.1` (включая проверку математического округления дробных цен и копеек).
- Настроен и применён обратный адаптер совместимости для бесшовного сопряжения старых клиентов v1 с новым API v2.
- Изучены механизмы идемпотентности запросов по уникальному ключу `pending` при имитации сетевых сбоев (`TIMEOUT_BEFORE`, `TIMEOUT_AFTER`).
- Успешно проведён выпуск (релиз) конфигурации 1.5.1 в рабочий контур с предварительным созданием снимка базы данных (`Snapshot`).
